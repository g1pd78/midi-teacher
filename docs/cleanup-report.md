# Отчёт: проверка и чистка кода

Этап без новых функций: поиск ошибок, разбор больших файлов, скорость, тесты. Поведение приложения не
менялось, кроме исправленных ошибок. Перепроверка — `docs/checklists/stage-cleanup.md` (раздел Р в
`docs/checklists/all.md`).

## Найденные и исправленные ошибки

| Что было | Когда проявлялось | Исправление |
|---|---|---|
| Поздний ответ ядра перезаписывал данные другой пьесы: цифры пальцев от прежнего тона, отрезки «Разучить» от прежней партии | Быстро нажать «Тон +/−» несколько раз или переключить партию песни туда-обратно | Ответы для прежней пьесы, тона или партии отбрасываются |
| Музыка продолжала играть на другом экране | «▶ Старт» в режиме ритма и сразу Esc (пока приложение сверяет часы с ядром) | Если экран уже закрыт — ритм не запускается или сразу останавливается |
| Терялась одна из двух правок настроек пьесы | Две правки настроек пьесы в одном действии, до перерисовки экрана | Правка берёт свежие настройки из хранилища, а не из прошлой перерисовки |
| Клавиши «залипали» на экране | Отключить MIDI-устройство с зажатой клавишей: «отпущено» уже не придёт | При отключении устройства его клавиши отпускаются |
| Паника при чтении WAV с испорченным заголовком (0 бит на сэмпл) | Только тестовые записи гитары | Отказ вместо паники |
| В сборку приложения попадала имитация ядра для браузера вместе с тестовыми файлами (Guitar Pro, песня Rocksmith) | Всегда (лишний код и файлы в установщике) | Имитация подключается только при разработке в браузере |

## Скорость

- **Запуск:** разделы грузятся отдельно, при запуске — только главная, остальное подгружается в фоне сразу
  после. Стартовый код интерфейса — **866 → 468 КБ** (без имитации и тестовых файлов).
- **Игра в темпе:** подсветка нот на стане находила элементы поиском по всему SVG на каждой перерисовке
  (~15 раз в секунду × каждая сыгранная нота). Теперь — по готовому указателю «нота → элементы», который
  строится один раз при отрисовке нот. HTML страниц нот больше не пересчитывается на каждой перерисовке.
- **Падающие ноты и дорожки** (клавиши, табы, барабаны, ритм): на каждом кадре перебираются только видимые
  ноты (двоичный поиск окна), а не вся пьеса; строки барабанной дорожки считаются один раз, а не на каждом кадре.
  Заметно на длинных MIDI с тысячами нот.
- **Открытие пьесы:** MEI пьесы разбирается один раз вместо трёх–пяти раз.
- **Настройки:** ползунок темпа и переключатели больше не записывают файл настроек на диск на каждое движение
  (запись в главном потоке приложения): первая правка — сразу, серия правок — одной записью в конце серии.

## Разбор кода

- `PieceView.tsx` — **2604 → ~2045 строк**: помощники и константы (`screens/piece/helpers.ts`), ведущий режим
  (`piece/GuidePanel.tsx`), итоги попыток (`piece/Summaries.tsx`), типы источника и упражнения (`piece/types.ts`),
  подсказки распознаванию гитары (`piece/useGuitarHints.ts`), переключатель (`components/Toggle.tsx`).
- Импорт MIDI (`midifile.rs`, 2021 строка) — модуль с подмодулями: тональность и написание нот (`key.rs`),
  выравнивание и руки (`quantize.rs`), запись станов MusicXML (`xml.rs`), запись своей игры (`smf.rs`).
- Общие части вместо копий: кнопка ступени `components/LevelCard.tsx` (было в пяти местах), барабанная партия
  из узоров `lib/drumPattern.ts` (было в двух местах).

## Тесты

- Юнит-тесты интерфейса: **163 → 172** — ступени гитарных аккордов (у каждого аккорда есть форма и она звучит
  как аккорд, серия без повторов, открытие ступеней, «минута смен»), барабанные узоры, окно падающих нот,
  сохранение настроек сериями и отпускание клавиш отключённого устройства (хранилище с заглушкой ядра).
- Ядро: проверка чтения испорченного WAV.
- Сквозной тест проходит целиком на изменённом коде. Замер по разделам: весь прогон — **~6 минут** (без сборки
  приложения); дольше всего гитарные аккорды и бой (~70 с) и чтение с листа (~60 с) — там бот играет в реальном
  темпе. Узких мест нет, ускорять не стал.

## Что осталось

- `PieceView` всё ещё самый большой файл (~2000 строк): режимы ожидания и ритма можно вынести в хуки
  (`useWaitMode`, `useRhythmMode`). Это отдельный рефакторинг с ручной проверкой всех режимов, без спешки.
- Аудио и устройства в ядре (`audio.rs`, `devices.rs`) не трогал: они проверены на оборудовании в прошлых этапах,
  явных ошибок при чтении не нашёл.
- Идеи по интерфейсу (в этом этапе не менял; сделаны следующим мини-этапом — чеклист `stage-ui.md`):
  - на грифе подписи открытых струн слева мелкие и перекрываются отметками на 0-м ладу;
  - в длинных списках упражнений (гитара, бой) нет свёртывания разделов;
  - в строке песни по буквам для гитары маленькие схемы аккордов теснят выбор боя на узком окне.
