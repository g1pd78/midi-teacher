# MIDI Teacher — техническая архитектура

План продукта, этапы и тестирование: [PLAN.md](PLAN.md).

Десктопное приложение для обучения игре на фортепиано с MIDI-клавиатурой.
Пользователь выбирает трек (MusicXML или MIDI) и играет его по интерактивному
нотному стану. Подсказки постепенно убираются, пока пьеса не будет выучена наизусть.

---

## 1. Требования, которые определяют архитектуру

| Требование | Что из этого следует |
|---|---|
| Отзывчивость: звук сразу после нажатия | Синтез звука в нативном коде, без браузерного Web Audio. Цель: меньше 10–15 мс от клавиши до звука |
| Точная оценка ритма | Время нажатия фиксируется в нативном потоке MIDI при получении события, а не в UI |
| Интерактивный нотный стан | Нужен качественный движок нотной графики с привязкой нот ко времени |
| Не думать о технике | Автоподключение MIDI-устройства, «горячее» переподключение, встроенный звук рояля, никаких настроек на старте |
| Выучить до уровня «без подсказок» | Движок практики: разбивка на фрагменты, уровни подсказок, автоматический переход между ними |

## 2. Варианты реализации

| Вариант | Задержка звука | Нотный стан | Скорость разработки | Итог |
|---|---|---|---|---|
| **A. Tauri 2: ядро на Rust + интерфейс на Web** | Отлично (звук в Rust) | Отлично (Verovio) | Высокая | **Рекомендуется** |
| B. Чистый Rust (wgpu/egui, как Neothesia) | Отлично | Плохо: зрелого движка нот на Rust нет | Средняя | Хорош для «падающих нот», слаб для нот |
| C. Electron + Web Audio | 20–40 мс на Windows | Отлично | Очень высокая | Не выполняет главное требование |
| D. C++ / JUCE | Лучшая (ASIO) | Всё рисовать самим | Низкая | Избыточно |
| E. Qt/QML + C++ | Отлично | Сложно (движок MuseScore тяжело встроить) | Низкая | Избыточно |
| F. Godot / Unity | Хорошо | Плохо | Средняя | Игровой движок, ноты не для него |

### Почему вариант A

Всё, что должно работать быстро, выполняется в Rust: приём MIDI, синтез звука,
часы воспроизведения, оценка нажатий. Всё, что должно красиво выглядеть, рисует
Web-интерфейс: ноты (Verovio), «падающие ноты», виртуальная клавиатура.

Задержка между Rust и WebView (около 1 мс) влияет только на картинку, а не на звук
и не на оценку. Для визуальной реакции этого более чем достаточно.

## 3. Архитектура

```
┌──────────────────────────── Rust-ядро (src-tauri) ────────────────────────────┐
│                                                                               │
│  MIDI-клавиатура ──► midi::Input (midir, поток с высоким приоритетом)         │
│                         │  NoteOn/Off + временная метка в мкс                 │
│                         ├──────────────► audio::Synth (rustysynth + cpal)     │
│                         │                   звук рояля из SoundFont, 3–10 мс  │
│                         ▼                                                     │
│                   engine::Transport ◄── аудио-часы (эталон времени)           │
│                         │                                                     │
│                   engine::Judge ── сверяет нажатия с ожидаемыми нотами        │
│                         │          (режим ожидания / режим ритма)            │
│                         ▼                                                     │
│                   practice:: ── фрагменты, уровни, статистика ──► SQLite      │
│                         │                                                     │
└─────────────────────────┼─────────────────────────────────────────────────────┘
                          │ Tauri events (позиция, ноты, результат оценки)
                          │ Tauri commands (загрузить трек, темп, цикл, режим)
┌─────────────────────────▼──────────── Web-интерфейс (src) ────────────────────┐
│  Нотный стан (Verovio WASM, SVG)  │  Падающие ноты (Canvas/WebGL)             │
│  Виртуальная клавиатура           │  Библиотека, настройки, прогресс          │
└───────────────────────────────────────────────────────────────────────────────┘
```

### Ключевые принципы

1. **Rust — единственный источник правды о времени.** Часы воспроизведения
   ведутся по аудиопотоку. Интерфейс получает `(позиция, момент)` и плавно
   интерполирует между обновлениями через `requestAnimationFrame`.
2. **Звук на нажатие не проходит через UI.** Событие MIDI сразу уходит
   в синтезатор внутри Rust.
3. **Одна модель нот для всего.** Каждая нота имеет `id`, который совпадает
   с `xml:id` элемента в SVG Verovio. Благодаря этому оценка из Rust
   подсвечивает ровно ту ноту на стане.

## 4. Технологический стек

### Rust (ядро)
| Задача | Crate |
|---|---|
| Оболочка приложения | `tauri` 2.x |
| Ввод MIDI | `midir` (Windows MM/WinRT, CoreMIDI, ALSA) |
| Вывод звука | `cpal` (ASIO + WASAPI на Windows, CoreAudio, ALSA/PipeWire) |
| Синтезатор | `rustysynth` (SoundFont .sf2) |
| Чтение MIDI-файлов | `midly` |
| Хранилище | `rusqlite` (SQLite в каталоге данных приложения) |
| Межпоточная передача | `crossbeam-channel` / кольцевой буфер `rtrb` для аудиопотока |
| Сериализация | `serde` |

### Интерфейс
| Задача | Библиотека |
|---|---|
| Язык / сборка | TypeScript + Vite |
| UI-фреймворк | React (или Svelte, это вопрос вкуса) |
| Нотный стан | `verovio` (WASM): MusicXML → SVG + временная карта (timemap) |
| Падающие ноты | Canvas 2D на старте, PixiJS (WebGL), если понадобится |
| Состояние | Zustand |

### Звук рояля
SoundFont с бесплатной лицензией (например, Salamander Grand Piano в формате sf2,
CC BY). Файл кладётся в ресурсы приложения. Отдельно нужен вариант «звук
с самой клавиатуры» (MIDI Out), если у инструмента есть свои динамики:
тогда задержка синтеза равна нулю.

### Бюджет задержки (от клавиши до звука)
```
USB MIDI           ~1 мс
Обработка в Rust   <0.1 мс
Буфер аудио        128–256 сэмплов @ 48 кГц = 2.7–5.3 мс
Драйвер/ОС         2–10 мс (WASAPI shared ~10, ASIO/CoreAudio ~3)
────────────────────────────
Итого              ~5–15 мс   (человек замечает задержку примерно от 20–30 мс)
```

## 5. Модель данных

```rust
struct Score {
    title: String,
    tempo_map: Vec<TempoChange>,        // тик → мкс
    time_signatures: Vec<TimeSig>,
    measures: Vec<Measure>,             // границы тактов в тиках (для циклов и фрагментов)
    notes: Vec<Note>,
    steps: Vec<Step>,                   // ноты, сгруппированные по одновременному началу (аккорды)
}

struct Note {
    id: String,          // = xml:id в SVG Verovio
    pitch: u8,           // номер MIDI
    start_tick: u32,
    duration_ticks: u32,
    hand: Hand,          // Left / Right
    measure: u32,
    finger: Option<u8>,  // из MusicXML <fingering>, если указано
    tied_from_prev: bool // продолжение лиги: заново нажимать не нужно
}

struct Step { start_tick: u32, note_ids: Vec<String> }
```

### Импорт MusicXML (основной формат)
1. Интерфейс загружает файл в Verovio: `loadData(musicxml)`.
2. Verovio отдаёт SVG (для отображения) и временную карту `renderToTimemap()`.
3. Для каждой ноты берём высоту, время и длительность (`getMIDIValuesForElement`)
   и номер нотоносца. Для фортепиано нотоносец 1 — правая рука, 2 — левая.
4. Готовый список нот уходит в Rust (`load_score`). Дальше им пользуется только ядро.

Так одна библиотека выступает единым источником и картинки, и тайминга: ноты
на стане и ноты в оценке не могут разойтись.

### Импорт MIDI
1. `midly` читает файл в Rust.
2. Руки: берём по дорожкам (если дорожек две или они подписаны), иначе делим
   по точке раздела с учётом движения голосов.
3. Выравнивание по сетке (квантизация) до 1/16 или триолей.
4. На первом этапе MIDI показывается только как «падающие ноты» с клавиатурой.
   Позже из выровненного MIDI генерируется MEI/MusicXML и передаётся в Verovio,
   чтобы появился нотный стан. Verovio напрямую MIDI не читает.

## 6. Движок оценки (engine::Judge)

### Режим ожидания (основной для разучивания)
- Текущий шаг = набор высот, которые нужно нажать (с учётом выбранной руки).
- Шаг засчитывается, когда нажаты все его ноты. Порядок внутри аккорда не важен,
  допускается разброс ~150 мс.
- Ноты под лигой и ноты, которые ещё звучат с прошлого шага, заново не требуются.
- Неправильная нота подсвечивается красным и записывается в статистику,
  но воспроизведение не двигает.
- Партию второй руки (если она не разучивается) играет синтезатор, подстраиваясь
  под продвижение ученика.

### Режим ритма (проверка)
- Воспроизведение идёт в заданном темпе, часы не останавливаются.
- Каждой ожидаемой ноте ищется ближайшее несопоставленное нажатие той же высоты
  в окне допуска: ±50 мс — «точно», ±120 мс — «нормально», дальше — «мимо».
- Пропущенные ноты и лишние нажатия считаются ошибками.
- Результат: процент верных нот, среднее отклонение по времени, раньше/позже.

### Общее
- Педаль (CC64) учитывается: отпускание клавиши при нажатой педали не считается
  обрывом ноты.
- Все события попытки сохраняются. Из них строится «тепловая карта» трудных
  тактов прямо на нотном стане.

### Тестирование
Оценка — чистая функция `(ожидаемые ноты, поток нажатий) → результат`.
Покрывается unit-тестами на синтетических последовательностях без
клавиатуры и UI.

## 7. Движок практики: от подсказок к игре по памяти

Это центральная идея приложения: одна и та же пьеса проходится много раз,
и подсказки постепенно исчезают.

### Фрагменты
Пьеса автоматически делится на фрагменты по 2–4 такта (`practice::split_fragments`).
Фрагмент режется на конце фразы, если в нём уже 2 такта, и в любом случае на 4.
Конец фразы (ищет интерфейс, `lib/practice.ts`): двойная, финальная или репризная
черта; долгая нота мелодии в конце такта (не короче половины такта); пауза во
второй половине такта. Одинокий последний такт присоединяется к соседу.
Границы правятся вручную (клик по такту в режиме «Границы…») и хранятся для пьесы.

### Уровни подсказок для каждого отрезка
| Уровень | Что видно | Режим | Темп |
|---|---|---|---|
| 0. Знакомство | Всё; приложение играет обе руки | Ритм, руки ученика — «никакие» | 80% |
| 1. Полные подсказки | Падающие ноты, подсветка клавиш, курсор, названия нот | Ожидание, руки отдельно | — |
| 2. Ноты с курсором | Стан + курсор, падающие ноты и подсветка ещё есть | Ожидание, обе руки | — |
| 3. Только ноты | Стан с курсором, без падающих нот и подсветки | Ритм | 60% → 100% |
| 4. По памяти | Такты отрезка закрыты на стане, падающих нот нет | Ритм | 100% |

Каждый уровень играется по кругу (цикл по тактам отрезка); после каждого круга
интерфейс отправляет проход в `practice_record`, а ядро (`practice::record`) решает:
- **Предложить дальше:** 3 хороших прохода подряд (точность ≥ 95%). На уровне 1
  серия считается для каждой руки отдельно; на уровне 0 достаточно одного прослушивания.
- **Темп уровня 3** растёт сам на 10% после каждого хорошего прохода; серия
  считается только в полном темпе. 3 плохих прохода подряд (< 80%) снижают темп.
- **Предложить вернуться:** 3 плохих прохода подряд (на уровне 3 — на стартовом темпе).
- **Выучено:** 3 хороших прохода по памяти. Отрезок отмечается выученным навсегда.
- Решает ученик: предложение можно принять или отклонить, уровень меняется вручную.

Точность прохода: в ожидании — нужные ноты / (нужные + лишние нажатия);
в ритме — попадания / (нужные + лишние).

- **Сцепление фрагментов:** 1 → 2 → 1+2 → 3 → 1–3 → … пока не соберётся вся пьеса.
  Отдельный фрагмент начинается с уровня 0, сцепка уже знакомых — с уровня 2.
  «Текущий» отрезок — первый невыученный в этом порядке.
- **Повторение с интервалами** отложено (бэклог).

### Хранилище (SQLite, `progress.db`)
```
pieces(id, title, measures, phrase_ends, hands, custom_starts, opened_at)
practice_units(piece, from_m, to_m, state JSON, updated_at)      -- уровень, серии, темп, выучено
practice_attempts(id, piece, from_m, to_m, level, mode, hands, tempo, accuracy, duration_ms, finished_at)
attempt_measures(attempt, measure, errors)                         -- тепловая карта
play_time(bucket, seconds)                                         -- 15-минутные корзины
```
Время игры: каждое нажатие клавиши добавляет паузу с прошлого нажатия, если она
не длиннее 30 с. Корзины по 15 минут позволяют разложить время по дням
в местном часовом поясе в интерфейсе.

## 7а. Аппликатура

Источники по приоритету: ручная правка (хранится для пьесы, таблица
`fingerings(piece, note_id, pitch, finger)`) → аппликатура из файла (`<fingering>`
в MusicXML) → автоматический подбор (`mt_core::fingering`).

**Подбор** — динамическое программирование по шагам (ноты с общим началом),
отдельно для каждой руки. Для шага перебираются все возрастающие наборы пальцев
(аккорд из k нот — C(5, k) вариантов); известные пальцы фиксируют набор. Стоимость
(упрощённая модель Parncutt и др., 1997, рука «обычная»):
- для каждой пары пальцев — удобные расстояния в полутонах (MinPrac…MaxPrac);
  выход за «расслабленный» диапазон — 1 за полутон, за удобный — ещё 2, за
  возможный — ещё 10;
- подкладывание первого пальца / перекладывание через него — +1, другие
  перекрещивания — +20; тот же палец на другую клавишу — +4 и больше;
- первый палец на чёрной клавише +2, пятый +1, четвёртый палец +0,3;
- после паузы длиннее 0,9 с переход стоит в 4 раза дешевле (рука переставляется).
Левая рука считается как зеркальная правая (высоты с обратным знаком).
Противоречивые известные пальцы (например, 5 ниже 1 в аккорде правой) не
соблюдаются — такие ноты подбираются заново.

**Показ:** интерфейс убирает `<fing>` из MEI и вставляет свою цифру у каждой ноты
(правая рука — над нотой, левая — под); подобранные помечаются `type="auto"`
(в SVG класс `auto`, серые), ручные — `type="manual"` (синие). Те же цифры
рисуются в падающих нотах и на подсвеченной клавише. В «Разучить» — на уровнях 0–2.

## 7б. Упражнения и теория

**Упражнения** генерируются кодом (`src/lib/exercises.ts`) как MEI со знаками при ключе
и стандартной аппликатурой (`<fing>`), играются на экране пьесы в режиме упражнения.
Каталог (~120 вариантов): пять пальцев (4 позиции), узоры в духе Ганона, мажорные гаммы до
3 знаков (каждой рукой, расходящаяся, параллельно, две октавы), гармонический и
мелодический минор, арпеджио. Раздел открывается ключевым упражнением, варианты внутри —
по порядку. Результат (точность, разброс ритма, ровность громкости, зачёт) хранится в
`exercise_results`.

Оценка — по событиям режима ритма (`hit` несёт силу нажатия):
- точность = попадания / (нужные + лишние);
- ровность ритма = стандартное отклонение сдвигов нот, отдельно — средний сдвиг на
  подкладывании/перекладывании пальцев;
- ровность громкости = 1 − коэффициент вариации силы нажатия; средняя сила по пальцам,
  «слабый» палец — заметно ниже среднего (< 88%);
- зачёт: точность ≥ 95%, разброс ≤ 60 мс, темп ≥ 100%.

**Разминка дня** — до 4 упражнений из открытого: передний край каждого раздела, иначе
пройденные, давно не игранные или неровные; выбор запоминается на день.

**Теория**: 28 карточек (`src/lib/theory.ts`) с нотными примерами из компактной записи
(`src/lib/snippet.ts`). Элементы пьесы находятся по MEI после Verovio (ключи, размер,
длительности, точки, лиги, знаки, динамика, педаль…). Показанные карточки — в настройках
(`theorySeen`).

## 7в. Импорт MIDI, запись, транспонирование

**Разбор** (`crates/mt-core/src/midifile/`, `midly`): дорожки делятся по (дорожка, канал) —
в файлах формата 0 все инструменты в одной дорожке. Темп, размер и тональность — первые
метасобытия файла (один темп на пьесу). Роли дорожек предлагаются сами: фортепианные
(программы 0–7) — «правая/левая» (по средней высоте) или «обе», прочие — аккомпанемент,
канал 10 — выключен.

**Перевод в ноты** (`convert`): сетка — 12 долей на четверть; для каждой доли выбирается
шестнадцатая (3) или триоль (4) — что точнее ложится под начала нот. Концы нот тоже по
сетке; ноту, отпущенную чуть раньше следующей (зазор ≤ max(шестнадцатая, ¼ промежутка)),
дотягиваем до неё. Дорожка «обе» делится на руки по аккордам: граница выбирается так,
чтобы ноты были ближе к текущим центрам рук, рука не шире децимы и не больше 5 нот; центры
плавно следуют за музыкой. Ручные правки рук — (начало в долях до обрезки, высота до
транспонирования, рука). Тональность — из файла или по профилям Крумхансла; написание нот
(диез/бемоль, вводный тон минора) — по тональности. Пустые такты в начале срезаются. Ноты
пишутся в MusicXML (два стана, лиги через такт, паузы, группировка, триоли) и дальше идут
обычным путём через Verovio. Аккомпанемент возвращается отдельно — нотами в мс, в сессиях
у них рука `accomp`: их всегда играет приложение, от ученика они не требуются.

**Команды** (`src-tauri/src/midi_import.rs`): `midi_inspect`, `midi_convert`, `midi_preview`
(начало дорожки звучит как «звук приложения»), запись `record_start/status/stop` (отсчёт и
метроном — щелчки встроенного синтезатора; все входы пишутся в SMF формата 0, 480 тиков на
четверть, темп и размер в файле; без щелчков время отсчитывается от первой ноты),
`save_text_file` (после диалога «Сохранить как»).

**Настройки пьесы** — `UiPrefs.pieceSetup[id]`: тон, роли дорожек, правки рук.
**Транспонирование**: MusicXML — опцией Verovio `transpose` при загрузке (id нот не
меняются, знаки при ключе пересчитываются); MIDI — в конвертере. Ручная аппликатура
хранится отдельно для каждого тона (`id@+2`).

## 7г. Гитара и бас: вход звука (этап Г0)

**Модуль** `crates/mt-core/src/guitar/`: `dsp.rs` — чистые вычисления (биквады, понижение
частоты ×4, высота методом Маклеода с уточнением на полной частоте, поиск начала ноты по
скачку энергии, тембр «чистый»/«перегруз», WAV); `mod.rs` — настройки, поток анализатора,
прослушивание, калибровка.

**Потоки.** Входной поток открывает аудиодвижок (`audio.rs`, тот же управляющий поток, что и
вывод): при выводе через ASIO вход — каналы того же драйвера (ASIO держит один драйвер на
программу), иначе — системное устройство записи (WASAPI). Входной колбэк берёт один канал,
умножает на усиление и кладёт сэмплы в две очереди без блокировок (`crossbeam-queue`):
анализатору и — через тембр — прослушиванию. Выходной колбэк подмешивает прослушивание
(`MonitorReader`: линейная интерполяция, подстройка скорости ±0,5% по заполнению очереди,
сброс лишнего, если выход отстал) — так вход и выход могут работать на разных частотах и часах.

**Анализатор** (свой поток): уровень и пик (дБ, 50 мс), признак перегрузки, высота каждые
~21 мс по окну ~85 мс (медиана трёх для устойчивости стрелки), начала нот с временем по часам
приложения (номер сэмпла → время по отметке последнего входного буфера), запись WAV.
Тестовый сигнал (`guitar_test_signal`) подаётся прямо в анализатор — так сквозной тест
проверяет тюнер без звуковой карты.

**Калибровка**: приложение щёлкает 8 раз, ученик бьёт по заглушённым струнам; у каждого
щелчка ближайший удар в ±300 мс, задержка — медиана сдвигов (хранится в `GuitarConfig.latencyMs`,
понадобится для оценки ритма на этапе Г1). Спрос на открытый вывод у гитары свой
(`set_guitar_sound_demand`), чтобы конец игры в ритме не выключал прослушивание.

## 7д. Гитара и бас: табы, распознавание нот, GM (этап Г1+Г2)

**Табы** (`src/lib/tab.ts`) строятся из MEI Verovio: выбранный стан превращается в табулатуру
(`staffDef notationtype="tab.guitar"`, `<tabGrp>` со значком ритма, у ноты `tab.course`/`tab.fret`),
**id нот сохраняются** — курсор, оценка, «Разучить» и прогресс работают как с обычными нотами.
Октава партии выбирается так, чтобы ноты легли на гриф (гитара — к ре первой октавы, бас — к до
большой); ноты за краем грифа переносятся на октаву. Раскладка по струнам и ладам —
динамическое программирование: растяжка пальцев, высокие лады, переезды руки, прыжки через
струны; продолжения лиг — на той же позиции. Готовые табы из файла берутся как есть.
Прогресс гитары/баса хранится под id `пьеса#guitar` / `#bass`; остальные партии пьесы звучат
аккомпанементом.

**Распознавание** (`crates/mt-core/src/guitar/notes.rs`): начало ноты — скачок энергии;
высота — через 12 мс после атаки по окну ≈2,5 периода самой низкой струны (гитара ~50 мс, бас
~95 мс; время ноты при этом — момент атаки); смена высоты без щипка (2 замера подряд) — новая
нота; затухание ниже 6% пика — конец. Подсказка: пьеса сообщает ожидаемые ноты
(`guitar_expect`), и ошибка на октаву исправляется в их пользу, если период альтернативы заметен
в сигнале. Ноты уходят в `DeviceManager::inject_event` как «устройство» «Гитара (звук)» /
«Бас (звук)» без маршрутов звука — все режимы получают их как MIDI. Время поправляется на
задержку из калибровки. Сквозной тест подаёт синтезированные щипки через `guitar_test_signal`
и проходит «Оду к радости» в табах целиком.

**GM-банк** (GeneralUser GS, закреплённый коммит, SHA-256 в `scripts/fetch-soundfont.mjs`) —
второй синтезатор в аудиодвижке, смешивается с роялем. Ноты аккомпанемента MIDI несут канал и
инструмент дорожки (`PieceNote.channel/program`), сессии выдают `GmNoteOn/Off`; без банка
аккомпанемент звучит «звуком приложения», барабаны пропускаются. Прослушивание дорожек в окне
дорожек — тоже через GM.

## 7е. Барабаны на пэдах и запись в пьесе (этап «Б»)

**Пэды** (`DeviceSettings.pads`, `devices.rs`): пэд — это пара «устройство, канал, нота» и
барабан (нота ударных GM: 36 бочка, 38 малый, 42/46 хэт закрытый/открытый, 48 том, 43 напольный,
49 крэш, 51 райд). В `on_midi` удар по назначенному пэду не идёт по маршруту клавиш: он звучит
барабаном GM-банка (канал 10; без банка — щелчок) и приходит в приложение нотой GM от
«устройства» «Пэды». Поэтому ожидание, ритм, «Разучить», запись и оценка работают с барабанами
без изменений — сравнение идёт по высоте ноты. Экранные пэды — команда `hit_drum` (тот же путь).
Мастер на вкладке «Барабаны» снимает назначения, ловит по удару на каждый барабан и сохраняет.

**Ноты** (`src/lib/drums.ts`): партия — такты-сетки (4 клетки на четверть — шестнадцатые, 3 —
триоли), из них MEI с ударным ключом: руки штилями вверх, бочка вниз; место на стане —
`@loc`, звук — `@pnum` (по нему Verovio отдаёт высоту); тарелки — крестики, открытый хэт —
«o», акцент — `artic="acc"`, тихая нота — `head.mod="paren"`, руки П/Л — подписи под нотами.
Грувы (14) и рудименты (9) — каталог со ступенями, статистика — в общей таблице упражнений
(`drum-…`). Экран игры в режиме барабанов: дорожка по барабанам (`DrumHighway`) и пэды
(`DrumPads`) вместо падающих нот и клавиатуры. Сила удара: акцент засчитан, если удар громче
обычных ×1,15, тихая нота — тише ×0,75 (сравнение с собственными ударами — у пэдов разная
чувствительность; одинаковая сила у всех ударов — оценка пропускается).

**Барабаны из MIDI**: роль дорожки «Барабаны» (`TrackRole::Drums`); конвертер выдаёт
барабанную партию по тактам (сетка такта — по большинству четвертей) и ноты рук как
аккомпанемент; интерфейс строит из неё ту же MEI. Инструмент «Барабаны» у пьесы появляется,
когда такая партия есть; файл из одних ударных открывается сразу барабанами.

**Запись в пьесе** (`RecordTake`): ● пишет всё, что играешь (с каналами: пэды — на 10-й), ■
оставляет дубль в памяти (`record_take_stop`); его можно прослушать (`record_take_play`:
клавиши — звуком приложения, пэды — барабанами GM), сохранить в библиотеку или выбросить.

## 7ж. Студия: свой трек из дорожек

**Модель** (`crates/mt-core/src/song.rs`): трек — темп, размер, число тактов и дорожки. У дорожки —
вид (клавишные, барабаны, бас, гитара, другое), инструмент GM (у клавишных без инструмента —
рояль приложения), громкость, «выкл»/«соло», дубли и выбранный дубль, сетка выравнивания с силой.
Время нот — мс от начала первого такта. Выравнивание не меняет дубль: применяется при
воспроизведении, экспорте и на ленте. Трек из MIDI-песни: каждая дорожка файла — дорожка трека
с дублем «Оригинал». Треки хранятся JSON в `Документы\MIDI Teacher\Треки` (автосохранение).

**Голоса**: клавишные без инструмента — каналы 1–8 рояля приложения, барабаны — канал 10 GM,
остальные — свободные каналы GM со своим инструментом; громкость — CC 7 в начале.
`song_events` выдаёт события с учётом «выкл»/«соло», сетки и исключения записываемой дорожки
(целиком или только перезаписываемого куска).

**Запись поверх** (`src-tauri/src/studio.rs`): `studio_play` играет события с такта, щёлкает
метроном и отсчёт; при записи все входы (клавиши, пэды, гитара по звуку) пишутся во времени
трека (`origin_us` — момент нулевой мс по часам приложения). `studio_stop` возвращает ноты и
педаль; интерфейс делает из них дубль: кусок склеивается с выбранным дублем, к оригиналу песни
считается точность (та же высота в ±120 мс; верные / (оригинал + лишние)).

**Экспорт**: многодорожечный SMF формата 1 (имя, инструмент, громкость, ноты с сеткой) — в
«Мои файлы»; WAV — офлайн-сведение теми же SoundFont (рояль приложения и GM-банк), стерео
44,1 кГц, нормализация к −1 дБ.

## 7з. Доводка (этап 7)

**Версия сборки**: Vite подставляет `__BUILD_SHA__` (в CI — `GITHUB_SHA`, локально — `git rev-parse`)
и `__BUILD_DATE__`; «Настройки → О программе» показывает первые 7 символов и ведёт на список
запусков CI ветки. Автообновления нет (решение пользователя): новая сборка — по кнопке.

**Резервная копия** (`src-tauri/src/backup.rs`): файл `.mtbackup` — JSON с `settings.json`,
снимком базы прогресса (`VACUUM INTO` во временный файл, base64) и треками студии
(`Документы\MIDI Teacher\Треки\*.json`). Восстановление кладёт `settings.json.restore` и
`progress.db.restore` рядом с рабочими файлами (пока приложение работает, оно само их
перезаписывает), а при запуске `apply_pending` подменяет ими рабочие до чтения настроек и
открытия базы (журналы `-wal`/`-shm` старой базы удаляются). Треки студии записываются сразу.
После восстановления — кнопка «Перезапустить сейчас» (`restart_app`).

**Интерфейс**: редкие настройки пьесы (строка/страницы, тон, дорожки и руки MIDI, MusicXML) —
в меню «⋯» (`MoreMenu`, Esc перехватывается и закрывает только меню); окно горячих клавиш
(`Hotkeys`) по «?» / F1 из любого экрана, пока оно открыто — клавиши не доходят до экрана.

## 7и. Чтение с листа и ритм

**Генераторы** (`src/lib/reading.ts`, `src/lib/rhythm.ts`) — чистые функции «ступень + зерно → ноты»:
одно зерно — одна и та же мелодия (тесты, «Ещё раз»), «Новая мелодия» — следующее зерно. Мелодия
строится по гармонии I–IV–V–I: первая нота такта — звук аккорда, дальше шаги и скачки по гамме
не больше разрешённого ступенью, в конце — тоника; левая рука — бас аккорда целыми или половинными.
Запись — MEI через `exerciseMei` (один стан или фортепианная система). Ритм — однолинейный ударный
стан (`lines="1"`, одна или две строки П/Л), высоты условные: 72 — правая строка, 48 — левая.

**Сопоставление нажатий** (`KeyMap` в `mt-core/src/piece.rs`): `exact` — обычная игра; `anyKey` —
любая клавиша или пэд превращается в 72; `byHand` — клавиши от до первой октавы и выше → 72, ниже → 48,
пэды: бочка и томы → 48, остальные → 72. Поле `keyMap` есть у настроек ожидания и ритма; хабы Tauri
применяют его к нажатию до сессии (знают, что нажатие пришло от «Пэдов»).

**Экран игры**: чтение и ритм — упражнения общего экрана (`ExerciseContext`): начальные подсказки
ступени, свои пороги зачёта, зачёт и в режиме ожидания (`waitRecord`: доля нот без ошибочных нажатий),
«▶ Послушать» (режим «в темпе» с руками «никакие», без оценки, потом обратно), для ритма — дорожка
из 1–2 строк (`DrumHighway` со своими строками) и площадки `RhythmPads` вместо клавиатуры.

**Зачёт и ступени**: результаты — в `exercise_results` (id `read-N`, `read-N-wait`, `rhythm-line-N`,
`rhythm-hands-N`); `exercise_stats` считает засчитанные попытки (`passes`), `exercise_history` —
попытки по префиксу за период (шаги «Занятия на сегодня», столбики «Прогресса»). Ступень чтения
пройдена после 3 засчитанных мелодий (из них одна в темпе), ритма — после 3 ритмов.


## 7к. Аккорды и песни по буквам

**Аккорды** (`src/lib/chords.ts`): разбор обозначений (C, Am, G7, Fmaj7, Bdim, Caug, Csus4, C/E, H),
состав по интервалам, написание звуков буквами (ми♭ в до миноре), названия; расположения аккорда в
диапазоне и голосоведение — следующее расположение ближе всего к предыдущему; распознавание: точный
набор нот (`identify`, бас — нижняя) и по нотам отрезка (`detectChordFit`: вес звука — длительность,
бас весомее; септима и основной тон должны звучать заметно; половины такта — только если целый ложится плохо).

**Тренажёр** (`src/lib/chordDrill.ts`): ступени, серия из 10 без повторов подряд (на «Обращениях» — случайный
бас), проверка нажатых клавиш (`judgeChord`: те же звуки в любой октаве; с обращением — нижняя нота).
Клавиши, зажатые до появления аккорда, не учитываются, пока их не отпустят или не нажмут заново.

**Песни** (`src/lib/songs.ts`): время — шестнадцатые; мелодия (у встроенных — мини-запись `e4q d4e …`),
аккорды — текстом по тактам («C | Am | F G | -»), затакт. `arrange` строит партии рук фактурой
(аккорд целиком, бас + аккорд, Альберти; без мелодии — правая аккорды, левая бас), `songMei` — MEI с
разбиением длительностей на записываемые (лиги через такт и долю), знаками и буквами `<harm>`.
Песня из пьесы (`songFromScore`): мелодия — верхний голос правой руки, аккорды — `<harm>` из MEI
(MusicXML с обозначениями) или распознанные по тактам. Свои песни — в настройках (`prefs.songs`,
ядро хранит как есть), поэтому попадают в резервную копию.

**Засчитывание по буквам**: `KeyMap::LeftAnyOctave` (ноты левой руки — в любой октаве) и `AnyOctave`
(без мелодии — обе руки); точное совпадение важнее, одна клавиша не засчитывается за две ноты разных рук.

## 7л. Строи и песни Rocksmith

**Строй инструмента** — в настройках гитары (`GuitarConfig.tuning`, `capo`; `None` — стандартный).
Ядро берёт самую низкую звучащую струну: от неё нижняя граница частот определения высоты
(`Instrument::range_from`) и окно распознавателя нот — пониженные строи (Drop C, бас в Drop D) слышны.
Интерфейс: выбор строя (готовые, свой по струнам, каподастр) и тюнер со струнами строя (`components/Tuner.tsx`:
струна определяется сама — ближайшая открытая, настроенные отмечаются ✓).

**Табы под строй** (`meiToTab(…, { tuning, capo, relayout })`): позиции раскладываются под звучащие открытые
струны (строй + каподастр), лады — от каподастра. Готовые табы из файла берутся как есть со строем файла
(`readTuning`); `relayout` раскладывает их заново под другой строй (те же звуки, ноты ниже нижней струны — на октаву
выше). Строй пьесы: у песни Rocksmith — из файла, у табов MusicXML — из `<staff-tuning>`, у остальных — свой выбор
(`PieceSetup.tuning/capo`) или строй инструмента. Если звучащие струны пьесы и инструмента разные — плашка:
«Перестроить» (тюнер на строй пьесы, «Готово» сохраняет его как свой) или «Переложить табы» (`PieceSetup.relayout`).

**Ноты над табами** (`withStaff`): обычный стан перед станом таба (в `staffGrp` — первым, номер таба остаётся 1),
ноты — копии нот таба с id `<id>~s` (в оценку не идут, подсветка дублируется), знаки — по такту; штили таба
убираются (ритм показывает стан).

**Песни Rocksmith (CDLC)** (`mt-core/src/rocksmith`): архив PSARC (заголовок, оглавление под AES-256-CFB с
открытым ключом формата, блоки zlib) → партии SNG (AES-256-CTR, ключи PC/Mac; разбор массивов до уровней
сложности). Открываются только пользовательские песни — в архиве должен быть `toolkit.version` (его кладут
инструменты для CDLC); официальные DLC игры отклоняются. Ноты — полная сложность: для каждой фразы её уровень
`maxDifficulty`, аккорды раскладываются по шаблону, «игнорируемые» ноты пропускаются; строй, каподастр, такты
(первая доля такта — маска доли), секции — из партии и манифеста. Формат сверен с Rocksmith2014.NET (MIT),
тестовые файлы оттуда — `crates/mt-core/tests/fixtures/rocksmith` (JSON-копия для тестов интерфейса и имитации —
`src/lib/fixtures/rocksmith-test.json`, обновляется тестом ядра).

Интерфейс (`src/lib/rocksmith.ts`): `rsChart` — партия → MEI-табулатура: темп постоянный (медиана долей),
позиции — номер доли + доля внутри неё, квантованные к шестнадцатым или триолям (что точнее в этой доле);
длительности — до протяжки или следующей ноты (без протяжки — до конца доли), лиги через долю и такт элементами
`<tie>`; приёмы — подписи над нотами (H, P, ↗/↘, B½, ~, PM, X, Harm, P.H., T, S/Pop…), секции — подписи и двойная
черта перед новой (границы фрагментов «Разучить»). `rsAccompaniment` — остальные партии звучат (электрогитара,
бас-гитара; такт — для фрагментов и циклов). Библиотека принимает `.psarc` (название — из имени файла
CustomsForge), команда `rocksmith_open` читает файл в фоне. Оригинальная запись песни (аудио) не используется.

## 7м. Guitar Pro и текстовые табы

**Общая модель** (`src/lib/tabsong.ts`, `TabSong`): такты файла (размер, ключевые знаки, части песни), порядок
звучания (повторы развёрнуты; номер прохода — для куплетов слов), смены темпа в такте и партии: гитара/бас
(струна и лад у каждой ноты, строй, каподастр), фортепиано и мелодии (обычные станы), барабаны (ноты GM).
Доля: начало и длина в тиках (960 на четверть), записанная длительность, точки, триоль/квинтоль, ноты, слова,
текст, аккорд. Verovio меняет темп только с начала такта, поэтому темп такта — средний по такту (длительность
как в оригинале), и аккомпанемент считается по той же карте (`barTempos`, `barStartsMs`).

`partChart` — MEI партии: таб со строем файла (позиции из файла, `meiToTab` берёт их как есть, все голоса),
станы с ключами, знаками при ключе и случайными знаками по такту, или ударный стан (`drumMei` с темпом и
частями по тактам); неполные группы триолей дополняются паузами той же группы, лиги — элементами `<tie>`,
приёмы и аккорды — подписи над долей, части — подпись и двойная черта (границы фрагментов), слова — `<verse>`.
`songAccompaniment` — остальные партии для приложения: свой канал GM у каждой (барабаны — 9), инструмент из
файла, ноты под лигой слиты. Тест сверяет время каждой ноты в Verovio с моделью (±3 мс).

**Guitar Pro** (`src/lib/gp.ts`): .gp3/.gp4/.gp5 и .gp (GP7–8) разбирает alphaTab (MPL-2.0; грузится только при
открытии такого файла). Порядок тактов с повторами, вольтами и переходами (D.S., D.C., Coda, Fine) и смены темпа —
из его генератора MIDI (как играет Guitar Pro). Тип партии — по инструменту GM (у любой дорожки GP есть «струны»):
24–31 — гитара, 32–39 — бас, 0–7 — фортепиано, ударные — барабаны, прочие — мелодия (табы, если у дорожки
только табулатура). Позиции — записанные (форшлаги не сдвигают ноту), переполненные такты обрезаются.

**Текстовые табы** (`src/lib/asciitab.ts`): системы из 4–7 строк-струн, такты — по чертам, общим для строк,
строй — по буквам слева (ближайшая к стандартной октава), лады (двузначные — до 24), x, h/p, / \, b (цифра после —
высота бенда), ~. Ритм: по расстоянию между цифрами в такте (с поправкой на отступ после черты, сетка
шестнадцатых) или ровно восьмыми/шестнадцатыми/четвертями. Темп, размер, каподастр и ритм — из строк текста;
окно «Вставить таб» пишет их первой строкой сохранённого .txt. Библиотека показывает .txt, только если в нём
есть таб (`looks_like_tab`).

**Экран пьесы** работает с любой песней из файла одинаково (`src/lib/filesong.ts`: Rocksmith, Guitar Pro, текстовый
таб): партии, MEI выбранной, аккомпанемент остальных; инструмент — по типу партии, прогресс — у каждой партии свой.

## 7н. Гитарные упражнения, гриф и теория (этап Г3)

**Упражнения** (`src/lib/guitarExercises.ts`) — код, а не файлы: каждое строит `TabSong` под открытый строй
пользователя (вкладка «Гитара»: строй выбранного инструмента; лады те же, звуки — по строю). Узор — последовательность
(струна, лад, палец); палец пишется подписью над нотой (как приёмы), `partChart` даёт таб, PieceView играет его как
упражнение (`exercise.instrument = "guitar" | "bass"`, подсказка `hint`, пороги `GTR_PASS`: 90%, ±70 мс — распознавание
звука добавляет разброс). Паучок — перестановки пальцев 1-2-3-4 по всем струнам вверх и обратно (диагональ — со
сдвигом позиции, «на двух струнах» — попеременно). Пентатоника, гаммы и арпеджио — `positionNotes`: звуки лада в окне
позиции (4 лада, у гамм — с растяжкой на лад ниже), от нижнего основного тона до верхнего. Игра под барабаны — рифф
плюс партия барабанов из 16-шаговых битов; барабаны идут аккомпанементом (`songAccompaniment`, канал 9).
Открытие — как у фортепианных: внутри группы по порядку, разделы — после первого паучка (пентатоника, грувы),
пентатоники (гаммы) и гаммы соль мажор (арпеджио). Id — `gtr-…` и `bass-…`: своя статистика, разминка
«На сегодня» (`gtrWarmup`: паучок + одно открытое), в ядре не считаются фортепианной разминкой.

**Тренажёр грифа** (`src/lib/fretboard.ts`, `src/screens/FretTrainer.tsx`): 10 ступеней на инструмент — открытые
струны, найди ноту на струне (лады 0–5 → 0–12, натуральные → со знаками), точка на грифе → нота, нота на стане →
гриф (ключ с «8», октава важна), все места одной ноты (по струнам снизу вверх). Серия — 12 заданий (seed),
без повторов подряд. Звук не говорит, на какой струне играли, поэтому засчитывается высота: в «найди на струне» —
та же нота на этой струне в пределах ладов ступени, иначе — точная высота. Нажатия — по событиям MIDI (`useMidi`),
не по состоянию зажатых клавиш (короткое нажатие не теряется). Зачёт — 85% с первой попытки и до 6 с на задание,
результат — `exercise_record` с id `fret-<инструмент>-<ступень>`.

**Теория**: группа «Гитара и бас» в `THEORY_GROUPS` — 12 карточек с примерами табами (`tabExample` → `partChart`).
Для пьес в табах `tabFeatures` находит в MEI подписи приёмов (H/P, слайды, бенды, PM, ~, X, флажолеты), каподастр
и нестандартный строй — по ним плашка «Новое».

## 7о. Гитара: аккорды и бой (этап Г4)

**Аккорд по звуку** (`crates/mt-core/src/guitar/chord.rs`). Приложение сообщает, какие аккорды сейчас ждут
(`guitar_expect_chords`: ноты MIDI каждого кандидата; в ритме — текущий и соседние шаги). Пока список не пуст,
анализатор вместо одноголосого распознавания слушает удары: после начала ноты пропускает 40 мс (струны звучат не
одновременно), берёт окно 170 мс, спектр (своё БПФ, окно Ханна, дополнение нулями) и его пики 60–2000 Гц. Сверка с
кандидатом: звук аккорда «слышен», если есть пик на его частоте или на 2-й/4-й гармонике (если это не обертон другого
звука аккорда); пик «лишний», если он сильный (не ниже −18 дБ от максимума), до ~1 кГц и не объясняется гармониками
(до 12-й, с допуском на негармоничность) звуков аккорда или звуком аккорда в другой октаве; обертоны лишнего звука
отдельно не считаются. Из кандидатов берётся лучший. Засчитано (все классы высоты слышны, лишних нет) — наружу уходят
все ноты кандидата, иначе — слышные и лишние; дальше их оценивает обычная логика пьесы, как аккорд с клавиатуры.
Время нот — момент удара. Частые удары (окно < 70 мс до следующего) берут итог прошлой проверки того же аккорда.
`guitar_test_chord` подаёт синтезированный удар (щипки с разбросом 12 мс и затуханием) — для сквозного теста.

**Аппликатуры** (`src/lib/guitarChords.ts`): таблица открытых аккордов (лады и пальцы) и подвижные формы смещениями
от лада основного тона (пауэр, баррэ форм ми и ля — мажор, минор, 7, m7; maj7, m7♭5, dim7, 9, 6, m6 от 6-й и 5-й
струны); без указания формы берётся открытая, иначе самая низкая позиция. Под другой строй лады пересчитываются на
те же звуки (струна, которой не дотянуться, глушится). Проверка в интерфейсе (`judgeGuitarChord`) — по классам высоты:
все звуки аккорда (квинту септаккорда можно пропустить) и ничего чужого. `ChordDiagram` — квадратик SVG
(пальцы, баррэ, × и ○, номер лада, красные/жёлтые струны после неверного удара).

**Тренажёр и смены** (`src/lib/guitarChordDrill.ts`, `src/screens/GuitarChords.tsx`): ступени — пулы аккордов с
формой; удар собирается из нот в окне 200 мс (`useStrum`: звук гитары в режиме аккорда приходит сразу, MIDI — с
разбросом). Зачёт ступени — 80% с первого удара и до 8 с (`gchord-N`). «Минута смен» — два аккорда по очереди
60 с; результат хранится как точность = смен/100 (`gchange-A-B`), зачёт — от 30 смен.

**Бой** (`src/lib/strum.ts`): схема — клетки такта («D», «U», «-»), размер и узор барабанов. `strumSong` строит
`TabSong`: удар вниз — все струны формы, вверх — верхние 3–4, стрелка подписью над верхней нотой, название аккорда —
над первым ударом; удар длится до следующего, если это пишется одной нотой. Упражнения «Бой» — раздел гитарных
упражнений (открыт сразу), песни по буквам — `songStrumBars` (аккорд на каждую клетку, такт сжимается до 1/2/4
аккордов) и `GuitarSongView` (PieceView с заданным инструментом и полосой схем над нотами).

## 7п. Устройство кода после чистки

- Экран пьесы: `src/screens/PieceView.tsx` (состояние, режимы, события ядра, разметка) и `src/screens/piece/` —
  `helpers.ts` (раскладка Verovio, рамки тактов, константы), `GuidePanel.tsx` (ведущий режим), `Summaries.tsx`
  (итоги), `types.ts` (`PieceSource`, `ExerciseContext`), `useGuitarHints.ts` (ожидаемые ноты и аккорды для
  распознавания звука). Подсветка нот берёт элементы SVG из указателя, построенного при отрисовке.
- Разделы приложения грузятся отдельно (`React.lazy` в `App.tsx`) и подгружаются в фоне после запуска. Имитация ядра
  (`src/mock.ts`) подключается только в режиме разработки (`import.meta.env.DEV`).
- Падающие ноты и дорожки (`Waterfall`, `TabHighway`, `DrumHighway`) перебирают только видимое окно
  (`firstAtOrAfter` по нотам, отсортированным по началу).
- Настройки интерфейса пишутся сериями (`savePrefs` в `store.ts`): первая правка — сразу, следующие в течение
  150 мс — одной записью.
- Гитарные упражнения на каждый день: `prefs.daily` (id упражнений «★ каждый день», хранится в настройках и в
  резервной копии); `gtrWarmup` — ★, паучок по кругу из засчитанных (по номеру дня), следующий новый паучок и одно из
  других разделов. Свёрнутые разделы — `localStorage` (`mt-gtr-collapsed`).
- Импорт MIDI: `crates/mt-core/src/midifile/` — `mod.rs` (разбор, роли дорожек, `convert`), `key.rs`, `quantize.rs`,
  `xml.rs`, `smf.rs`.

## 7р. Слух

- Задания: `src/lib/ear.ts` — виды (`interval`, `chord`, `degree`, `melody`, `rhythm`), ступени `EAR_LEVELS`
  (id упражнения `ear-<вид>-<N>`, открытие по порядку внутри вида), генерация серии `earSeries(level, seed, guitar)`
  (ноты с временем, варианты ответа, ожидаемые высоты, пояснение) и проверки: `judgeNote` (класс высоты; октава — не
  та же клавиша), `judgeChordPlay` (набор классов высот), `melodyPrefix`, `judgeRhythm` (первый удар совмещается с
  первым началом, допуск 0,22 доли, лишние удары — штраф). Ритмы — генератор ритм-тренажёра (`rhythmScore`),
  запись нотами — `rhythmMei`. Ступени в тональности начинаются с каденции I–IV–V–I (`cadence`).
- Звук: команда `play_notes(notes, program)` — тот же поток проигрывания, что у прослушивания MIDI
  (`spawn_playback`, новый вызов обрывает прежний). С `program` (гитара — GM 25) и загруженным GM-банком ноты идут во
  встроенный синтезатор на канал 2, иначе — «звук приложения».
- Экран: `src/screens/Ear.tsx` — список ступеней (`LevelCard`), выбор тембра (`localStorage` `mt-ear-timbre`) и три
  вида заданий: кнопки + ответ игрой (`useMidi` — нота, `useStrum`/`useExpectChords` — аккорд, в т. ч. гитарой по
  спектру), мелодический диктант, ритмический (прослушать → отсчёт → удары → вердикт и ноты). Итог серии пишется
  через `exercise_record`; зачёт — от 80% с первой попытки (серия 10, диктанты 5).
- «Занятие на сегодня»: шаг «Слух» (сделан, если сегодня есть результат `ear-%`); кнопка открывает раздел и сразу
  серию (вид по номеру дня, текущая ступень). Результаты `ear-%` не входят в счёт фортепианной разминки (`store.rs`).

  при переподключении. При первом запуске — короткий тест «нажми любую клавишу».

## 10. Этапы

### Этап 0. Каркас и звук (главный технический риск)
- Tauri-приложение, список MIDI-устройств, автоподключение.
- Нажатие клавиши → звук рояля из Rust → подсветка на виртуальной клавиатуре.
- Экран измерения задержки.
- **Готово, когда:** задержка звука субъективно незаметна, звук чистый без щелчков.

### Этап 1. Интерактивный нотный стан (ядро продукта)
- Открыть MusicXML → нотный стан через Verovio → ноты уходят в Rust.
- Автовоспроизведение с курсором.
- Режим ожидания: курсор идёт вперёд при правильном нажатии, ошибки красным.
- Руки отдельно; вторую руку играет синтезатор.
- **Готово, когда:** можно сесть и сыграть простую пьесу (например,
  «Менуэт соль мажор» из нотной тетради Анны Магдалены Бах) по нотам с подсказками.

### Этап 2. Падающие ноты, темп, циклы
- Падающие ноты и клавиатура синхронно с нотами.
- Темп 30–120%, цикл по выделенным тактам, метроном.
- Режим ритма с оценкой.

### Этап 3. Практика и прогресс
- Фрагменты, уровни подсказок, автоматическое повышение и понижение уровня.
- SQLite: попытки и ошибки; тепловая карта на стане.
- Экран библиотеки с прогрессом.

### Этап 4. MIDI-файлы
- Импорт MIDI, разделение рук, квантизация → падающие ноты.
- Генерация нот из MIDI → Verovio.

### Этап 5. Доводка
- Аппликатура: из MusicXML, позже автоматический подбор.
- Сцепление фрагментов, повторение с интервалами.
- Установщики: Windows (NSIS/MSI), macOS (dmg), Linux (AppImage).
- Опционально: звук через MIDI Out на встроенный синтезатор клавиатуры.

| Риск | Как снижаем |
