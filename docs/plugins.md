# Плагины MIDI Teacher

Плагин добавляет в приложение то, чего нет в основном коде. Пока ни одного плагина не установлено, интерфейс
никак не показывает, что они бывают.

## Установка

Папка плагина кладётся в папку `plugins` данных приложения:

- Windows: `%APPDATA%\com.g1pd78.miditeacher\plugins\<id>\`
- Linux: `~/.local/share/com.g1pd78.miditeacher/plugins/<id>/`

Плагины читаются при запуске. Новый плагин подхватывается после перезапуска приложения или перезагрузки окна
(Ctrl+R).

## Состав

```
plugins/echo/
  plugin.json     манифест
  plugin.js       ES-модуль с функцией activate(host)
  storage.json    настройки плагина (создаёт приложение по host.storage.set)
  …               любые файлы плагина: WASM, модели, картинки
```

`plugin.json`:

```json
{ "id": "echo", "name": "Эхо", "version": "1.0", "api": 1, "entry": "plugin.js" }
```

| Поле | Что это |
|---|---|
| `id` | совпадает с именем папки; латиница, цифры, `-`, `_`, `.` |
| `name`, `version` | показываются в «Настройках → Плагины» |
| `api` | версия API хоста; сейчас `1`. Плагин с другой версией не загружается |
| `entry` | путь к модулю внутри папки плагина |

Файлы плагина отдаются по протоколу `mtplugin` — адрес даёт `host.url("путь")` (в Windows это
`http://mtplugin.localhost/<id>/<путь>`). Выйти за пределы своей папки нельзя.

Ошибка при загрузке или в `activate` записывается в журнал и в «Настройках → Плагины» («не загрузился: …»);
приложение и другие плагины работают дальше.

## API хоста, версия 1

```js
export async function activate(host) {
  host.registerSettings({ title: "Мой плагин", mount(el) { el.textContent = "…"; } });
}
```

Типы — в `src/plugins/host.ts` (`PluginHost`).

| Метод | Что делает |
|---|---|
| `onMidi(cb)` | ноты с инструментов: `{ type: "on" \| "off", pitch, velocity, device, timeUs, receivedAt }`; `receivedAt` — `performance.now()` в момент прихода. Возвращает отписку |
| `onPieceStep(cb)` / `expected()` | шаг пьесы или упражнения в режиме ожидания: `{ index, notes: [{ pitch, hand, finger }] }`, `finger` — палец по аппликатуре (1–5) или `null`; `null` вместо шага — пьеса закрыта |
| `reportFinger({ pitch, finger, hand? })` | каким пальцем нажата клавиша. Хост сверяет с аппликатурой: не тот палец — жёлтая отметка на схеме ладоней и на стане; в итоге попытки — строка «Пальцы: 87% верно, чаще всего 3 вместо 4 — такты 5–6», на экране «Прогресс» — точность по дням |
| `setConfirmHits(on)` | режим подтверждения: верное нажатие засчитывается после `reportFinger` (верный палец) или `confirm`. Не тот палец — ошибка, шаг стоит. Нет ответа за 300 мс — нажатие засчитывается как обычно |
| `onPending(cb)` | верная клавиша ждёт подтверждения (в режиме подтверждения) |
| `confirm(pitch, ok)` | подтвердить или отклонить ждущее нажатие без сверки пальца |
| `registerSettings({ title, mount })` | свой раздел в «Настройках» |
| `registerPieceOverlay({ mount })` | своё окно в правом нижнем углу экрана пьесы |
| `storage.get()` / `storage.set(value)` | свои настройки — JSON в `storage.json` папки плагина |
| `url(path)` | адрес файла плагина |
| `log(...)` | запись в консоль с именем плагина |

`mount(el)` получает пустой элемент и может вернуть функцию уборки. `registerSettings` и
`registerPieceOverlay` возвращают функцию, которая убирает раздел или окно.

Сообщение о пальце может прийти позже нажатия: хост сопоставляет его с нотами текущего шага и шагов за
последние 1,5 с. Каждая нота сверяется один раз. Ноты без аппликатуры не сверяются.

## Лицензия

Плагин загружается внутрь программы, поэтому по GPL считается её частью. Пока плагин не распространяется,
это ничего не требует. Если распространять — тоже под GPL-3.0-or-later.

## Пример

Тестовый плагин сквозного теста — `e2e/fixtures/plugins/echo/`: раздел в настройках, окно в пьесе и
сообщения о пальцах по аппликатуре (верно, неверно или молча).
